# nollama

**The model runner Ollama should have been.**

One Go binary. Plain GGUFs. Transparent llama-server under the hood. Federation across your fleet.

## Quickstart

```bash
# Install nollama
curl -fsSL https://raw.githubusercontent.com/sovereignty-labs/nollama/main/install.sh | sh

# Build llama-server with CUDA support (~3 min, requires git + cmake + nvcc)
nollama runtime build

# Or download a pre-built CPU runtime (no build tools needed)
# nollama runtime install

# Find a model
nollama search gemma 4 12b

# Pull it
nollama pull bartowski/gemma-4-12b-it-GGUF:Q4_K_M

# Run it
nollama run gemma-4-12b-it-Q4_K_M
```

Six commands from zero to interactive chat. No Docker. No account required.

## What This Is

nollama is a process manager for [llama-server](https://github.com/ggerganov/llama.cpp) (llama.cpp's built-in HTTP server). It handles the tedious parts — building or downloading the right binary for your hardware, computing optimal flags from GGUF metadata, managing multiple models across multiple GPUs, routing requests — while staying completely out of the inference path.

When you send a prompt to nollama, it proxies the HTTP request to the right llama-server process. Pure reverse proxy. Zero overhead on the hot path. Every token is generated by llama.cpp, unmodified.

## What This Is Not

nollama is not a platform. It does not have a cloud offering. It does not have a model registry. It does not have a blob store. It will never have any of these things.

If you want a GUI, point [Open WebUI](https://github.com/open-webui/open-webui) at nollama's endpoint. If you want cloud fallback, use [LiteLLM](https://github.com/BerriAI/litellm). If you want a platform, build one on top — nollama exposes a standard OpenAI-compatible API.

## Why Not Ollama

Ollama wraps the same engine (llama.cpp) but adds layers between you and your models that cost performance, flexibility, and transparency:

| | Ollama | nollama |
|---|---|---|
| **Model storage** | Proprietary blob store with hashed filenames | Plain GGUFs in a directory |
| **Config format** | Modelfile (reimplements what GGUF already contains) | Read the GGUF. Use CLI flags. No Modelfile. |
| **Chat templates** | Hardcoded list of known templates | `--jinja` — llama-server reads the GGUF-embedded template |
| **Inference overhead** | Additional processing layer over llama.cpp | Pure HTTP proxy. Zero overhead. |
| **Quantization** | Limited selection | All llama.cpp quantizations |
| **Multi-GPU** | No | Per-model GPU assignment with VRAM-aware defaults |
| **Multi-node** | No | Federation — manage models across machines from any terminal |
| **Fork support** | No | Run TurboQuant, ik_llama, or any llama-server fork per-model |
| **Flag transparency** | Hidden | `--dry-run` shows every flag. `--` passes anything through. |
| **Cloud inference** | Yes | No. Local only. |

## Interactive Chat

`nollama run` is the fastest path from model to conversation:

```bash
nollama run gemma-4-12b-it-Q4_K_M

# Resolves the model, spawns llama-server with smart defaults,
# waits for health, drops you into an interactive chat.
#
# > What's the fastest sorting algorithm for nearly-sorted data?
#
# Thinking tokens are displayed dimmed. Ctrl+C or /exit to quit.
```

If `nollama serve` is already running with the model loaded, `nollama run` connects to the existing instance instead of spawning a new one.

Multi-line input uses backslash continuation:

```
> Write a haiku about \
  local inference
```

Exit with `/bye`, `/exit`, `/quit`, `exit`, `quit`, or Ctrl+C.

Find models on HuggingFace without leaving the terminal:

```bash
nollama search qwen3 8b
# REPO                                    DOWNLOADS  QUANTS
# unsloth/Qwen3-8B-GGUF                   542,103    Q2_K, Q4_K_M, Q8_0, ...
# bartowski/Qwen3-8B-GGUF                 128,447    IQ4_XS, Q4_K_M, Q6_K, ...
# ...

nollama search deepseek r1 distill
nollama search gemma 4 27b
```

Results are sorted by downloads. Top 10 GGUF repos shown.

### HuggingFace Token

Some repos require authentication. Store your token once:

```bash
nollama token set hf_your_token_here
# Stored at ~/.config/nollama/token (permissions: 0600)

# Check what's stored
nollama token show

# Remove it
nollama token rm
```

The token is used automatically by `nollama pull` and `nollama search`. Also respects the `HF_TOKEN` environment variable.

## Smart Defaults

When you run `nollama load model.gguf`, nollama reads the GGUF header and your hardware to compute optimal flags:

```bash
$ nollama load gemma-4-27b-Q4_K_M.gguf --dry-run

  Model:    gemma-4-27b-Q4_K_M.gguf (15.2 GB)
  Arch:     Gemma4 (MoE, 27B total, 4B active)
  Quant:    Q4_K_M
  Template: Jinja (embedded in GGUF ✓)
  Context:  131,072 (from GGUF metadata, fits in VRAM)
  Target:   GPU 0 (RTX 3090, 24GB — 18.4 GB estimated)

  Would run:
    llama-server \
      --model /models/gemma-4-27b-Q4_K_M.gguf \
      --n-gpu-layers 99 \
      --ctx-size 131072 \
      --flash-attn on \
      --jinja \
      --host 0.0.0.0 \
      --port 11435 \
      --no-warmup

  Override anything: nollama load model.gguf -- --ctx-size 65536 --parallel 4
```

No magic. Every decision is visible. Every flag is overridable.

## Runtime Management

nollama manages the llama-server binary. Two options depending on your setup:

### Build from source (recommended for GPU)

Official llama.cpp releases don't include CUDA builds for Linux. If you have an NVIDIA GPU, build from source — nollama handles the entire process:

```bash
nollama runtime build
# Clones llama.cpp, detects CUDA/nvcc, runs cmake + make.
# ~3 minutes. Requires: git, cmake, make, a C++ compiler, and nvcc (CUDA toolkit).
```

Build a fork for advanced features like TurboQuant KV cache compression:

```bash
nollama runtime build \
  --repo https://github.com/nicholasyager/llama-cpp-turboquant \
  --name turbo

nollama runtime build \
  --repo https://github.com/ikawrakow/ik_llama.cpp \
  --name ik-llama
```

### Download pre-built (CPU only on Linux)

```bash
nollama runtime install
# Downloads the latest llama.cpp release binary.
# Auto-detects platform. On Linux this is CPU-only — use runtime build for GPU.
```

### Multiple runtimes

```bash
# Different models on different forks simultaneously
nollama load model-a.gguf --runtime turbo
nollama load model-b.gguf --runtime mainline

# Switch the default
nollama runtime use turbo

# Point at your own binary
nollama runtime add custom /opt/my-llama/build/bin/llama-server

# List installed runtimes
nollama runtime list
# NAME          VERSION  SOURCE   ACTIVE
# llama-build   —        build    ✓
# llama-b9279   b9279    release
# turbo         —        build
```

## Multi-GPU

nollama detects your GPUs and assigns models to whichever has the most free VRAM. Override with `--gpu N`:

```bash
nollama load large-model.gguf --gpu 0     # RTX 3090, 24GB
nollama load small-model.gguf --gpu 1     # RTX 5060 Ti, 16GB
nollama load auxiliary.gguf --cpu          # CPU fallback
nollama status

# NODE   GPU              MODEL              VRAM         PORT
# local  RTX 3090 24GB    large-model        22.1/24.0GB  11435
# local  5060 Ti 16GB     small-model        14.2/16.0GB  11436
# local  CPU (64GB)       auxiliary           —            11437
```

Same model on multiple GPUs with different configs:

```yaml
autoload:
  - model: Qwen3-30B-A3B-Q4_K_M.gguf
    alias: agent-fleet
    gpu: 0
    port: 8002
    flags:
      ctx-size: 131072
      parallel: 8

  - model: Qwen3-30B-A3B-Q4_K_M.gguf
    alias: deep-context
    gpu: 1
    port: 8001
    flags:
      ctx-size: 262144
      parallel: 1
```

## Federation

Register remote nollama nodes and manage your entire fleet from any terminal:

```bash
nollama remote add gpu-host http://gpu-host.example.internal:11434
nollama remote add inference-host http://inference-host.example.internal:11434

nollama status
# NODE   GPU              MODEL                  VRAM         PORT
# local  RTX 3090 24GB    Qwen3-30B-Q4_K_M       22.1/24.0GB  11435
# gpu-host   RTX 4090 24GB    gemma-4-27b-Q4_K_M     18.4/24.0GB  11434
# inference-host   CPU (128GB)      Qwen3-30B-BF16          —            11434

# Load a model on a remote node
nollama load model.gguf --node gpu-host

# Copy a model between nodes (over your LAN, not re-downloading)
nollama cp model.gguf --to inference-host

# Pull directly to a remote node
nollama pull unsloth/Qwen3-8B-GGUF:Q4_K_M --node gpu-host
```

No orchestrator, no consensus protocol, no automatic failover. Each node is sovereign. Federation is remote control over HTTP.

## Hardware Profiles

Named flag sets for common configurations:

```bash
# Built-in profiles
nollama load model.gguf --profile agent-fleet
nollama load model.gguf --profile turboquant-asymmetric

# Profiles are stackable
nollama load model.gguf --profile turboquant-asymmetric --profile agent-fleet
```

Profiles ship with the binary. Community profiles via PR.

## VRAM Management

When VRAM is full, swap models explicitly:

```bash
nollama load big-model.gguf --swap
# Evicts the least-recently-used model, loads yours.
```

No auto-eviction by default. You loaded that model for a reason.

## MCP Server

nollama exposes fleet management as [MCP](https://modelcontextprotocol.io/) tools. Any MCP-capable client (Claude Desktop, Open WebUI, custom agents) can manage your inference fleet programmatically:

```bash
nollama serve --mcp
```

Tools: `nollama_status`, `nollama_load`, `nollama_unload`, `nollama_models`, `nollama_pull`, `nollama_inspect`, `nollama_runtimes`, `nollama_rm`.

Control plane only — inference requests go through the OpenAI-compatible API, not MCP.

## Configuration

Config is optional. nollama works with zero config. The config file pre-defines what to load on startup:

```yaml
model_dir: /models
bind: 0.0.0.0:11434

autoload:
  - model: Qwen3-30B-A3B-Q4_K_M.gguf
    gpu: 0
    flags:
      ctx-size: 131072
      parallel: 4

  - model: Qwen3-8B-Q4_K_M.gguf
    device: cpu
    flags:
      ctx-size: 65536
      threads: 12

defaults:
  flash-attn: "on"
  no-warmup: true
  jinja: true
```

Default locations: `~/.config/nollama/config.yaml` or `/etc/nollama/config.yaml`

Send `SIGHUP` to reload config without downtime. nollama reconciles — unchanged models keep running, new ones load, removed ones unload.

## Passthrough

Every llama-server flag is available. nollama never hides options:

```bash
# Override anything after --
nollama load model.gguf -- --ctx-size 262144 --parallel 8 --cache-type-k q8_0

# See what would be passed without launching
nollama load model.gguf --dry-run
```

```bash
curl http://localhost:11434/metrics
```

Exported: loaded model count, per-model request count and idle time, GPU VRAM usage, system RAM. No external dependencies — hand-rolled text format.

## CLI Reference

```
nollama run <model>               Interactive chat (spawns server if needed)
nollama serve                     Start the daemon
nollama load <model> [flags]      Load a model
nollama unload <model>            Unload a model
nollama status                    Fleet-wide status
nollama models                    List available GGUFs
nollama inspect <model>           Show GGUF metadata
nollama search <query>            Search HuggingFace for GGUF models
nollama pull <org/repo:quant>     Download from HuggingFace
nollama cp <model> --to <node>    Copy model between nodes
nollama rm <model>                Remove a model file
nollama remote add/rm/list/ping   Manage remote nodes
nollama runtime build/install     Build or download llama-server
nollama runtime list/use/add      Manage llama-server binaries
nollama token set/show/rm         Manage HuggingFace token
nollama version                   Show build info
```

Model names resolve automatically: bare filenames like `model` check the current directory, then your configured `model_dir`, then the default models directory. The `.gguf` extension is optional.

## Install

**One-line install:**
```bash
curl -fsSL https://raw.githubusercontent.com/sovereignty-labs/nollama/main/install.sh | sh
```

**Binary download:**
```bash
# Linux x86_64
sudo curl -fsSL https://github.com/sovereignty-labs/nollama/releases/download/v0.1.0/nollama-linux-amd64 \
  -o /usr/local/bin/nollama && sudo chmod +x /usr/local/bin/nollama
```

```bash
git clone https://github.com/sovereignty-labs/nollama.git
cd nollama
go build -o nollama ./cmd/nollama
```

**systemd service:**
```bash
sudo cp nollama /usr/local/bin/
sudo cp systemd/nollama.service /etc/systemd/system/
sudo systemctl enable --now nollama
```


## Build Requirements

nollama itself is a static Go binary with no runtime dependencies.

`nollama runtime build` compiles llama-server from source and requires: `git`, `cmake`, `make`, a C/C++ compiler (`gcc`/`g++`), and optionally `nvcc` (CUDA toolkit) for GPU support. Build time is approximately 3 minutes on a modern machine. If CUDA is detected, the build enables GPU acceleration automatically.

`nollama runtime install` downloads a pre-built binary and requires no build tools. On Linux, official llama.cpp releases are CPU-only. On macOS, Metal support is included.
